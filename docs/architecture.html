Compiler architecture

Architecture & pipeline.

json-to-dom is organized around a strictly layered, zero-dependency compiler pipeline.

The v11 Orchestration Pipeline

buildSpecElement(inArgs)
  │
  ├─► orchestration/1.normalizeInput.js   ──► Extracts { spec, applyEvents, showLog }
  │
  └─► orchestration/2.dispatchSpec.js     ──► Routes spec by shape:
        │
        ├─► null / undefined              ──► returns null
        ├─► Node instance                 ──► passthrough
        ├─► Array of specs                ──► buildSpecArray() -> DocumentFragment
        │
        └─► Single spec object            ──► buildSingleElement()
                                                │
                                                ├─► buildChildrenNodes() (recursive)
                                                │
                                                └─► elementBuilder/ (steps 0 to 6):
                                                      0. createElement.js
                                                      1. applyTextContent.js
                                                      2. applyProperties.js
                                                      3. applyAttributes.js
                                                      4. applyClassList.js
                                                      5. appendChildren.js
                                                      6. applyEvents.js
                                                            │
                                                            ▼
                                                      events/ (chapters 1 to 3):
                                                        1.validate/isEventAllowed.js
                                                        2.internal/attachInternalEvents.js
                                                        3.declared/attachDeclaredEvents.js

Key Subsystems

  • Sleek v11 Orchestrator: src/v11/index.js reads as pure, sequential orchestration.
  • Element Builder: 7 dedicated steps (0 to 6) constructing pure native DOM elements.
  • Event Story: 3 modular chapters separating permission validation from internal hooks and declared listeners.
  • Runtime Inspection: getHookedEvents({ inElement }) and element.__ksEvents.

Evolutionary Progression

Version folders document the architectural journey:

  • v1-v7: Early prototypes and grammar research.
  • v8: Two-tier attribute resolution.
  • v9: Strict event guarding.
  • v10: Modular event story folders.
  • v11: Sleek orchestration-only index & granular event stopping.

Core Design Intent

  • Zero Dependencies: Pure Web Standards (document.createElement, addEventListener).
  • KeshavSoft Conventions: 100% adherence to { in... } / local... parameter mappings.
  • Clean Decoupling: Static DOM rendering carries zero event overhead unless explicitly required.
