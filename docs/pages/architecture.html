Two-Engine Architecture

How json-to-dom orchestrates tag synthesis and target mounting into a clean, zero-bloat pipeline.

The Two Subordinate Micro-Engines

1

Tag Synthesis Engine

@keshavsoft/json-to-tag

  • • W3C Validation: Checks tag names, allowed attributes, and HTML5 grammar.
  • • SVG Namespaces: Generates SVG, path, and polygon nodes with proper XMLNS namespaces.
  • • Pure Synthesis: Creates real browser DOM element trees in-memory without touching the live page.
npm: @keshavsoft/json-to-tag →
2

Target Mounting Engine

spec-to-dom

  • • Container Resolution: Safely resolves target container elements by HTML ID (document.getElementById).
  • • Collection Routing: Supports single elements, arrays, NodeLists, or DocumentFragments.
  • • Safe Mounting: Appends, prepends, or replaces content natively without risky innerHTML injection.
npm: spec-to-dom →
The Source Code

A 16-Line Orchestrator (`src/v42/index.js`)

At v42, all legacy bloat and internal parsing logic has graduated into specialized sibling packages. The orchestrator itself is minimal, robust, and transparent: 

import registerGlobal from "./register/index.js";
import jsonToTag from "@keshavsoft/json-to-tag";
import specToDom from "spec-to-dom";

const startFunc = ({ jsonSpec, targetHtmlId, appendPosition, showLog }) => {

    // 1. Synthesize native DOM nodes via jsonToTag
    const buildSpec = jsonToTag(jsonSpec);

    // 2. Mount synthesized nodes into target container via specToDom
    const container = specToDom({ buildSpec, targetHtmlId, appendPosition, showLog });

    return container;
};

// Register onto globalThis.ks.jsonToDom.appendToDom for CDN browser use
registerGlobal(startFunc);

export default startFunc;
