Rationale

Why this repo exists.

Imperative DOM manipulation and raw HTML string concatenation create repetitive churn, fragile maintenance, and security headaches. json-to-dom solves this by transforming serializable data into guarded DOM trees.

The problems it solves

  • Repetitive Churn: Replaces dozens of imperative createElement / appendChild calls with pure JSON specs.
  • Grammar Enforcement: Automatically checks tags and attributes against HTML specifications before DOM creation.
  • Decoupled Events: Separates static element construction from event listener attachment.
  • Zero Dependencies: No runtime bloat, no framework lock-in, no complex build tools required.

The architectural boundary

By keeping the input strictly JSON, the UI specification can be:

  • Stored in relational databases or NoSQL stores.
  • Generated dynamically by backend microservices.
  • Logged, snapshotted, and transferred over WebSockets.
  • Tested independently without mounting a browser DOM.

The tradeoff & scope boundary

  • Not a reactive framework: Does not perform Virtual DOM tree diffing on state changes.
  • Not a full platform: Does not include routing, global store management, or CSS bundling.

In one sentence: json-to-dom exists to turn serializable JSON specifications into live browser DOM element trees with zero dependencies and built-in W3C grammar validation.
