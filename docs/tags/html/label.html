The <label> Element Specification

Represents a caption or user-interface title for form controls. In json-to-dom, <label> is a non-void element capable of holding text nodes or nested children (e.g. required asterisks, tooltips, or icons) with strictly scoped attributes.

W3C Grammar Contract (from tags.json)

json-to-dom validates all <label> specifications against these rules before touching the DOM:

allowsTextContent
true
Carries primary human-readable text via textContent.
allowsChildren
true
Can nest child elements like <span>, icons, or badges.
Allowed Attributes (3):
for — Target input ID class — CSS classes id — Element ID
Any other attributes (e.g. placeholder, colspan, type) are automatically purged by filterAttributes.js.
tags.json definition v7 
"label": {
    "allowsTextContent": true,
    "allowsChildren": true,
    "allowedAttributes": [
        "for",
        "class",
        "id"
    ]
}

What Happens if You Pass Invalid Attributes?

If someone mistakenly adds an attribute like placeholder or colspan to a <label>, the json-to-dom validator steps in:

Invalid Spec:
{
  "tagName": "label",
  "textContent": "Email Address",
  "attributes": {
    "for": "user-email",
    "placeholder": "Should not be here!", // ❌ Disallowed
    "colspan": 2                          // ❌ Disallowed
  }
}
Result in DOM:

filterAttributes.js strips placeholder and colspan. The real DOM node receives only valid attributes:

<label for="user-email">Email Address</label>
