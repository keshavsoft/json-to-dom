Architecture & Engine Pipeline: The JSON-to-DOM Bridge

A technical deep dive into the module design, recursion model, guard boundaries, and low-level DOM element construction order of the json-to-dom engine.

Core Boundary Architecture

Specification World (JSON)

Pure serializable JavaScript/JSON objects. No DOM node instances, no browser layout reflows. Transformed freely by pipelines (Themes, Columns, Sorting).

DOM World (Browser Elements)

Live browser HTMLElement instances with event listeners, dynamic attributes, and live mutations. Created strictly at the final step.

1. Traversal Flowchart

When buildSpecElement({ inSpec }) is invoked, it traverses the JSON specification recursively in a bottom-up, depth-first manner:

flowchart TD Start(["buildSpecElement(inSpec)"]) --> Normalize["Normalize inSpec parameter"] Normalize --> CheckNull{"isNullOrUndefined?"} CheckNull -- Yes --> RetNull["Return null"] CheckNull -- No --> CheckDomNode{"isDomNode?"} CheckDomNode -- Yes --> RetDomNode["Return existing Node"] CheckDomNode -- No --> CheckArray{"isSpecArray?"} CheckArray -- Yes --> BuildArray["buildSpecArray()\nmap each item to buildSpecElement()"] BuildArray --> RetArray["Return Array of DOM Nodes"] CheckArray -- No --> CheckObject{"isSpecObject?"} CheckObject -- No --> RetNull2["Return null"] CheckObject -- Yes --> BuildSingle["buildSingleElement()"] BuildSingle --> BuildChildren["buildChildrenNodes(spec.children)\nRecursively calls buildSpecElement()"] BuildChildren --> RunBuilder["domElementBuilder(spec + resolved children)"] RunBuilder --> RetElement["Return constructed HTMLElement"]

2. Directory & Module Responsibilities

The core implementation in src/v2/build/ separates validation and tree navigation from DOM mutation:

Module Path Role & Description
buildSpecElement.js Primary entry point; parameter normalizer and high-level type dispatcher.
buildSpec/isNullOrUndefined.js Guard verifying whether input is null, undefined, or empty.
buildSpec/isDomNode.js Detects pre-existing DOM Node instances to support hybrid specs.
buildSpec/isSpecArray.js Detects array inputs representing fragments or multiple sibling elements.
buildSpec/buildSingleElement.js Recursively resolves children specs first before delegating to elementBuilder.
elementBuilder/index.js Executes the 5-step element instantiation and property assignment sequence.

3. The 5-Step Element Construction Sequence

In elementBuilder/index.js, each single element is constructed strictly in the following deterministic sequence:

  1. 1. Create Element: createElement({ inTagName }) calls document.createElement(localTagName).
  2. 2. Apply Text & Properties: applyTextContent sets textContent; applyProperties merges JavaScript DOM properties (e.g. checked, value, disabled) using Object.assign.
  3. 3. Apply Attributes & Classes: applyAttributes applies attributes via setAttribute (or sets className for class attributes); applyClassList parses space-delimited tokens into classList.add(...).
  4. 4. Bind Event Listeners: applyEvents registers callbacks via addEventListener(eventName, listener).
  5. 5. Append Pre-resolved Children: appendChildren attaches the already-instantiated child DOM nodes. 
const startFunc = ({ inSpec, inClassList }) => {
    const localSpec = inSpec;
    const localClassList = inClassList;

    if (!localSpec || !localSpec.tagName) return null;

    // 1. Create Element
    const element = createElement({ inTagName: localSpec.tagName });

    // 2. Apply Text Content & Properties
    applyTextContent({ inElement: element, inTextContent: localSpec.textContent });
    applyProperties({ inElement: element, inProperties: localSpec.properties });

    // 3. Apply Attributes & Classes
    applyAttributes({ inElement: element, inAttributes: localSpec.attributes });
    applyClassList({ inElement: element, inClassList: localClassList });

    // 4. Bind Event Listeners
    applyEvents({ inElement: element, inEvents: localSpec.events, inTagName: localSpec.tagName });

    // 5. Append Children
    appendChildren({ inElement: element, inChildren: localSpec.children });

    return element;
};

4. Architectural Coding Standards

Every function across this repository conforms to the in... and local... parameter convention:

  • All parameters are passed as a single object with properties prefixed by in (e.g., { inSpec, inElement }).
  • The first lines of the function assign these properties to local variables prefixed by local (e.g., const localSpec = inSpec;).
  • This guarantees parameter immutability, explicit scoping, and eliminates argument-ordering errors.
